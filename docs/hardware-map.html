Game Boy (DMG) — what's wired to what

The console is one SM83 core talking to everything over a single 16-bit address / 8-bit data bus. Each block is labeled with the package/ module that plays that chip.

Chip → module

Who plays what

  • SM83 core → Cpu.roc (state, step, interrupt dispatch) over Cpu/Instruction, Cpu/Alu, Cpu/Register; GameBoy.roc is the SoC composition only
  • Address/data bus + WRAM/VRAM/HRAM + the I/O page → Bus.roc
  • Timer → Timer.roc · joypad → Joypad.roc (pure units; the bus owns their register bytes)
  • PPU → Ppu.roc · APU → Apu.roc, with hidden channel state in Apu/Channel and NRxx field decode in Apu/Register
  • Cartridge (ROM, MBC banking, save RAM, RTC) → Cartridge.roc + Cartridge/Header.roc
  • LCD, speaker, buttons, battery → app/ray.roc and app/web/

Hardware truths

Why one bus explains it

  • Every component except the CPU is memory-mapped: the CPU configures the PPU, APU and timers by writing registers on the same bus it fetches code from
  • CPU registers are the exception — internal to the core, unreachable from the bus, which is why the CPU owns them; the APU's channel internals (timers, LFSR, envelopes) are hidden the same way in Apu/Channel
  • The PPU owns a second port into VRAM/OAM — during pixel transfer (mode 3) it locks the CPU out
  • Interrupts (VBlank, STAT, timer, serial, joypad) are the only other cross-wires into the CPU
  • The cartridge is not passive: its MBC chip decodes ROM writes as bank-switch commands

Emulator deltas

Where the code bends it

  • The PPU's dedicated VRAM port is not modeled: it reads through Bus.read / Bus.read_vram like everyone else
  • The APU's analog output becomes 48 kHz stereo F32 pushed into a ring buffer the bus owns
  • OAM and the peripheral register bytes live in the bus's flat mem, not inside the units that own them physically
  • No boot ROM — the core starts from documented post-boot state
  • Wall-clock time and buttons enter as per-frame data: run_frame({ buttons, now })
