# Recon notes (tasks 1.1–1.3), gathered 2026-08-10

Sources: `lukewilliamboswell/roc-wasm4@main` (pushed 2026-08-09), `torch2424/wasmBoy@master`, `binji/binjgb@main`, rtfeldman.com/rust-to-zig.

## 1.1 roc-wasm4 host wiring — the big news: already migrated to the new compiler

roc-wasm4 pins `nightly-2026-08-08-195c9e7` and is fully on the new Zig-based Roc compiler. What our platform needs to replicate:

**Platform header declares targets in a `targets:` block** — listing only wasm32 makes `roc build` default to emitting `.wasm`:

```roc
platform ""
    requires { [Model : model] for main : { init! : () => model, update! : model => model } }
    exposes [...]
    provides { "init_for_host": init_for_host!, "update_for_host": update_for_host! }
    hosted { "host_trace": Host.trace!, ... }
    targets: {
        inputs_dir: "targets/",
        wasm32: {
            inputs: ["host.wasm", app],
            output: Shared,
            exports: ["start", "update"],
            import_memory: Zeroed,
            minimum_memory: 65536, maximum_memory: 65536,   # WASM-4-only; ours: default 64MB
            initial_stack_size: 14752,                       # WASM-4-only tuning
            global_base: ...,                                # WASM-4-only
        },
    }
```

**Entrypoint/effect names in `provides`/`hosted` ARE the linker symbols** — the new compiler exports plain C-ABI functions (`extern fn init_for_host() RocBox`), no `roc__mainForHost_*_exposed` mangling. Roc-side wrappers Box the model: `init_for_host! = || Box.box(main.init!())`.

**build.zig emits a relocatable object, does not link** — `cpu_arch=.wasm32, os_tag=.freestanding, abi=.none, pic=true`, output copied to `platform/targets/wasm32/host.wasm`; the Roc compiler does the final link (`inputs: ["host.wasm", app]`). `minimum_zig_version = "0.16.0"`, zero deps. Platform bundle: `roc bundle platform/*.roc platform/targets/wasm32/*.wasm`.

**Host hooks the new compiler requires** (all `callconv(.c)` exports):
`roc_alloc(len, align)`, `roc_dealloc(ptr, align)`, `roc_realloc(ptr, new_len, align)`, `roc_dbg(bytes, len)`, `roc_expect_failed(bytes, len)`, `roc_crashed(bytes, len)`. Notably absent vs old compiler: no `roc_panic`, no memset/memcpy shims.

**`src/roc_platform_abi.zig` (~1050 lines) is auto-generated by the Roc glue generator** — RocStr/RocList/Box helpers, allocator vtable (prepends a size header since `roc_dealloc` gets no length), dbg/crash handlers. This is the file we regenerate for our platform; hand-written host logic is only ~420 lines. Ownership rule: Roc transfers ownership of refcounted args to hosted functions, which must decref.

**Do NOT copy** (64 KB survival gear): umm_malloc over a 32 KB static array, stack canaries after the framebuffer, `global_base` gymnastics, min=max memory 65536. Ours: default 64 MB memory, plain arena/`std.heap.wasm_allocator` behind the same `std.mem.Allocator` seam.

**Rocci Bird** lives inside roc-wasm4 (`examples/rocci-bird.roc`) — no separate repo; the migrated host above is the Rocci Bird host. rust-to-zig post: new compiler at feature parity, 0.1.0 planned later in 2026; `roc build --opt=size` emits a 31 KB wasm cart.

## 1.2 wasmboy JS contract → our spike export list

Minimal wasmboy headless sequence (from `test/core/save-state.js`):

```js
const mem = new Uint8Array(exports.memory.buffer);
mem.set(romBytes, exports.CARTRIDGE_ROM_LOCATION);
exports.config(0,1,1,0,0,0,1,0,0,0);
exports.setJoypadState(...8 i32s);
exports.executeMultipleFrames(5);                 // i32 status
const frame = mem.slice(exports.FRAME_LOCATION, exports.FRAME_LOCATION + exports.FRAME_SIZE); // RGB24
```

Proposed spike exports (GB-agnostic, constants + flat memory philosophy):

```
memory                                     // fixed 64MB — cached Uint8Array view is safe
ROM_LOCATION, ROM_MAX_SIZE                 // JS stages cart bytes here
FRAMEBUFFER_LOCATION, FRAMEBUFFER_SIZE     // 160*144*4 RGBA8 (skip wasmboy's RGB24 quirk)
init() / reset()                           // allocator + init_for_host
rom_loaded(len: u32) -> i32                // commit staged ROM
run_frame(buttons: u32) -> i32             // packed button bits; 0 ok / <0 error / >0 event bits
// later: SAVE_RAM_LOCATION/_SIZE, audio_ptr/audio_len/clear_audio
```

Packed-u32 buttons beat wasmboy's 8-arg setJoypadState. With 64 MB there's no need to pack regions tightly.

## 1.3 binjgb renderer seam → WebGPU translation

binjgb's seam (`docs/simple.js`): a `Video` class holds a `Uint8Array` view over the wasm framebuffer and delegates to a swappable renderer exposing exactly **two methods**: `uploadTexture(buffer)` (called on emulator frame-ready) and `renderTexture()` (called in `requestAnimationFrame`) — upload and present decoupled. WebGL path: 256×256 NEAREST texture, `texSubImage2D` upload, quad with UVs clipped to 160/256×144/256; Canvas2D fallback behind the same interface (12 lines).

WebGPU translation (full ~60-line reference sketch preserved in the recon report; key points):
- Texture exactly 160×144 `rgba8unorm` (no power-of-two padding needed), nearest sampler.
- Per-frame `device.queue.writeTexture({texture}, buffer, {bytesPerRow: 640, rowsPerImage: 144}, [160,144])` — `writeTexture` has NO 256-byte bytesPerRow alignment requirement (that's only buffer-to-texture copies), so the tight RGBA buffer works as-is.
- Fullscreen triangle (3 vertices from `@builtin(vertex_index)`, no vertex buffer), WGSL vs+fs sampling the texture, `pass.draw(3)`, submit per frame; canvas context via `getContext('webgpu')` + `configure({device, format: navigator.gpu.getPreferredCanvasFormat(), alphaMode: 'opaque'})`.
- CSS `image-rendering: pixelated` + nearest sampler handles upscaling.
- seyhajin/webgpu-wasm-zig: future host-side-WebGPU reference only (needs Emscripten — conflicts with wasm32-freestanding + Roc linking). mach-gpu / rayray: not applicable (deprecated / native-only).
